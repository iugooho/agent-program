# 错误码

前端只根据 `code` 判分支，**不要解析 `message` 文案**（文案会改，码不会）。
`code = 0` 表示成功，其余一律是失败；失败时 `data` 为 `null`，`message` 只给人看。

## 响应形状

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

失败时同时给出 HTTP 状态码与业务码：HTTP 状态用于网关、日志、监控的粗粒度判断，
`code` 用于前端精确定位。

## 码表

认证码值以《旅游规划智能体系统接口设计文档》为准；参数、路由和系统错误使用不冲突的扩展编号。

| code | HTTP | 含义 | 触发场景 |
| --- | --- | --- | --- |
| 0 | 200 | 成功 | - |
| 1000 | 400 | 参数校验失败 | `@Valid` / `@Validated` 不通过 |
| 1001 | 409 | 账号已存在 | 注册账号重复 |
| 1002 | 409 | 邮箱已存在 | 注册邮箱重复 |
| 1003 | 401 | 账号或密码错误 | 密码登录失败 |
| 1004 | 400 | 邮箱验证码错误或过期 | 验证码不匹配、过期或已使用 |
| 1005 | 403 | 账号已禁用 | 非 ACTIVE 用户登录 |
| 1006 | 401 | Refresh Token 无效或撤销 | 刷新令牌校验失败 |
| 1007 | 429 | 邮箱验证码发送过于频繁 | 60 秒内重复发送 |
| 1008 | 400 | 请求体格式错误 | body 不是合法 JSON、字段类型不匹配 |
| 1009 | 405 | 请求方法不支持 | 路径存在但 HTTP 方法不对 |
| 1010 | 428 | 需要人机验证 | 登录失败次数达到阈值，或敏感认证操作未提交 CAPTCHA 答案 |
| 1011 | 400 | 人机验证无效 | 答案错误、挑战过期、用途不匹配或已消费 |
| 1012 | 429 | 请求过于频繁 | IP 或业务操作超过 Redis 限流窗口 |
| 2000 | 404 | 行程不存在 | 按 ID 查行程查不到 |
| 2001 | 422 | 行程生成失败 | 模型或外部工具的结果拼不成行程 |
| 401 | 401 | 未登录或令牌失效 | 缺少、过期、伪造或已撤销的访问令牌 |
| 403 | 403 | 无访问权限 | 已登录但无权访问目标资源 |
| 404 | 404 | 资源不存在 | 路径没有匹配到接口 |
| 500 | 500 | 内部服务器错误 | 未预期异常，细节只进日志 |

## 怎么用

业务代码直接抛，不要自己 try-catch 拼响应：

```java
throw new BusinessException(ErrorCode.BAD_CREDENTIALS);
throw new BusinessException(ErrorCode.ACCOUNT_DISABLED);
```

- `ErrorCode`、`BusinessException` 位于 `com.travelagent.travelplanner.common.error`。
- 普通业务异常由 `GlobalExceptionHandler` 转成统一响应。
- Security 过滤器链中的 401 / 403 由入口点和拒绝处理器返回 `code=401/403`。
- 日志不得记录密码、JWT、Refresh Token 或邮箱验证码。
